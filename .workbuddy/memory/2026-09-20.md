## 技术报告 docx 公式排版修复

- 目标文件：`【技术报告】无人机低空航拍图像语义分割.docx`（`_原始模板.docx` 是官方大纲模板，仅标题，不含公式，未改）。
- 问题：公式全部是纯文本，不是 Word 原生公式。
  - `动态调制定义为 F′ᵢ = GN(Fᵢ) × [...] + ...。其中c是…动态融合为 F = Σᵢ softmax(g(c))ᵢ × Resize(Pᵢ(F′ᵢ))。` 整段里公式与中文说明混排，公式被折行切断。
  - `L = 0.55 L_focal-CE + 0.30 L_Dice + ...` 用 ASCII 下划线假下标，靠左不居中。
  - 表格内 `1×10⁻⁵` / `1×10⁻⁴` 用 Unicode 上标字符（U+207B/2074/2075）；公式里的 `ᵢ` 用 U+1D62 —— 靠字体回退渲染，字号/基线不一致。
- 处理：直接改 `word/document.xml`，按 `w14:paraId` 定点整段替换（`04EB92C8` / `4B5591EC` / `149E647E`），插入 5 个 `<m:oMath>`（3 个独立居中公式 + 2 个行内 `1×10^n`）。脚本：`.workbuddy/tmp_ed/fix_math.py`。
- 版式做法：公式段落用 `w:tabs`（center tab 4819 twips、right tab 9638 twips，A4 去 1134×2 边距）+ `w:jc=left`，实现「居中公式 + 右对齐式号」；变量斜体（不写 `m:sty`），函数名/数字/运算符加 `<m:sty m:val="p"/>` 正体，数字与函数名之间补显式空格 run。
- 结果：Word 识别到 5 个公式对象；段落 157→161、表格 6→6；渲染前后文本 diff 只有这三处公式区变化。

## 环境发现（重要）

- **`editor_sdk` MCP 本地文档编辑通道在当前环境不可用**：实例能进 pool，但任何 `doc_*` 读写都报 `document is not open`；`open_file` 只回 “open started，chunks streaming via /stream”，需要宿主前端消费 SSE 才真正加载，纯 MCP 调用驱动不了。
- `doc_to_image` 报 `COS upload failed (exit 9009)`，因为服务进程 PATH 里没有 curl。
- **非 ASCII（中文）路径 editor_sdk 解析不了**，会报 `file not found`（`open_file` 也只会留一条 `last_saved_ms=-1` 的空壳）。
- 可用的替代渲染链：PowerShell + Word COM `ExportAsFixedFormat($pdf, 17)` → pymupdf 逐页出 PNG（pymupdf 装在 `C:\Users\86189\.workbuddy\binaries\python\envs\default`）。PowerShell 工具不回显 stdout，把结果写文件再读。
