## 三、必须遵守的硬约束

1. **数据集一个字节都不能进包**（镜像里也不行）。手册明确禁止泄露、传播数据集。
   代码包里放 `runs/splits/{train,val,test}.txt` 这类**文件名清单**是允许且必要的，
   它保证了划分可复现；图像与掩码本身不放。
   `tools/export_server2_rootfs.py` 已经用 `--exclude` + `--one-file-system` 排除了
   `/root/hyperseg/dataset` 和所有挂载点，导出前务必用它的 `inspect` 动作再确认一次。
2. **只保留最终单模型**。手册禁止 multi-model ensemble，代码库里不要留集成推理入口，
   也不要放多份候选权重让人误以为做了集成。历史实验配置可以留，但要在
   `REPRODUCE.md` 里写明"最终提交使用哪一个检查点"。
3. **预测 ZIP 的文件名必须与输入完全一致**，单通道灰度 PNG，1024×1024，像素值 0..8。
   复赛的对象是测试集 2，与输入一一对应即可；半决赛要把三套合并，届时先查重名：
   本地已确认是 `test1_*` / `test2_*` 前缀，测试集 3 应为 `test3_*`；
   打包前要用集合运算确认 `test1 ∩ test2 ∩ test3 = ∅`，否则评测按文件名匹配会串。
4. **镜像里不要塞实验结果目录**：`LoveDA/`、`SUIM/`、`experiment/*/logs` 里的一次性产物、
   `__pycache__`、`/root/.cache/huggingface` 中与本次无关的模型、conda `pkgs` 缓存
   都应在导出前清理，能省下数 GB。
5. **权重按需瘦身**：训练时保存的检查点常带 optimizer 状态（本项目 H3 的 `best.pt` 约 2.3 GB，
   其中大部分是优化器张量）。提交包与镜像里只保留推理需要的
   `model` / `model_config` 字段，可把体积降到几百 MB。

## 四、镜像形态：给三级复现路径

| 级别 | 产物 | 体积 | 用途 |
| --- | --- | --- | --- |
| 一键启动 | AutoDL 控制台保存的系统镜像 | 云端，无需下载 | 我方留档、快速回到现场 |
| 完整镜像文件 | `rootfs.tar.gz` 分卷 | 约 5–8 GB | 交付给评审，`docker import` 即可还原 |
| 干净重建 | `Dockerfile` + `requirements.lock.txt` | 几 KB | 评审自行构建，验证环境可复现性 |

导出与导入约定（写进 `README_IMAGE.md`）：

```bash
# 导出（在服务器上，走仓库已有脚本，自动排除数据集与挂载点）
python tools/export_server2_rootfs.py inspect   # 先看排除列表与关键文件哈希
python tools/export_server2_rootfs.py export > rootfs.tar.gz   # 脚本内部已 tar | gzip -3，不要再套一层压缩

# 导入（评审侧）
docker import hyperseg-rootfs-<日期>.tar.gz hyperseg-uav:submit
docker run --gpus all -it hyperseg-uav:submit bash
```

`tools/export_server2_rootfs.py export` 的输出**本身就是 gzip 流**（内部 `tar | gzip -3 -n`），
所以直接重定向到 `.tar.gz` 即可，不要再接一次 `gzip`。

若走本地下载再转网盘，可用 `tools/download_server2_rootfs.py`：它会边流式下载边校验
（拒绝出现在排除列表里的路径、拒绝 `tmp/`、`run/` 瞬态内容、逐字节核对关键文件哈希），
但有两个前置条件——**本地需空出 24 GiB**，且它通过 `.tmp_server2_access.py` 读取
`sshconfig.toml` 的 `[server2]` 段，换到 server3 需要同步改这两处（脚本名、镜像文件名、
`REMOTE` 路径、段名）。

注意两点：`docker import` 导入的是**文件系统快照**，不是 `docker save` 的镜像归档，
两者不能混用；AutoDL 容器内没有 docker 守护进程，因此镜像只能在本地或评审侧重建，
服务器上只能导出 tar。

## 五、分卷与网盘上传

百度网盘官方帮助中心的单文件上限（2026-09 核对）：

| 账号类型 | Web 端 | Windows / Mac 客户端 |
| --- | --- | --- |
| 普通用户 | 1 GB | 4 GB |
| 会员 | — | 10 GB |
| 超级会员 | — | 20 GB |

因此**镜像必须分卷**，每卷留出余量按 3.8 GB 切：

```bash
split -b 3800M -d --numeric-suffixes=1 --suffix-length=2 \
      hyperseg-rootfs-<日期>.tar.gz hyperseg-rootfs-<日期>.tar.gz.part_
# 评审侧合并
cat hyperseg-rootfs-<日期>.tar.gz.part_* > hyperseg-rootfs-<日期>.tar.gz
curl -s -o - 校验用的 sha256  # 或直接 sha256sum，与 CHECKSUMS.sha256 比对
```

上传与分享注意：

- 用**客户端**上传（Web 端上限只有 1 GB）；分卷文件全部放在同一个网盘文件夹里，
  文件夹直接分享，避免逐文件分享漏项。
- 分享设置**永久有效 + 提取码**；把"链接 + 提取码"一起写进提交表单，
  不要只贴链接而把提取码留在正文里被截断。
- 再准备一个备选网盘（如腾讯微云、阿里云盘）放同一份内容，链接失效时能立刻补交。
- 上传完成后**从网盘下载一次并跑 `sha256sum -c CHECKSUMS.sha256`**，
  确认传输没有损坏；这一步是唯一能证明网盘副本可用的方式。

## 十、交付介质：E 盘读取不可靠（2026-09-30 实测）

**结论：GB 级交付物一律不要放在 E 盘。** 该盘为外置 USB 盘（exFAT），
实测会**偶发返回错误数据**，且同一文件重复读取会得到不同结果。

判定证据（同一批字节，同一命令）：

| 读取对象 | 结果 |
| --- | --- |
| `cat part_* \| sha256sum`，E 盘新目录 第 1 次 | `c541042f…` ✅ |
| 同一命令、同一数据，E 盘 第 2 次 | `81f52499…` ❌ |
| `cat part_* \| sha256sum`，E 盘旧目录 | `2eda57e1…` ❌ |
| 4 个分卷**单独** `sha256sum`（E 盘，多次） | 全部正确 ✅ |
| 同样 4 个分卷复制到 **D 盘**后逐卷校验 | 全部正确 ✅ |
| `cat part_* \| sha256sum`，**D 盘连续 3 次** | `c541042f…` ✅✅✅ |

即：数据本身是对的，**读取路径**会偶发出错。检查过的大小、只读位、目录可写性、
沙箱开关都不是原因；同一文件 `cmp` 判定「逐字节相同」而 `sha256sum` 给出不同哈希，
指向盘/USB 链路的静默读取错误。

**应对**：

1. 完整交付目录改在 **D 盘内盘**组装：`tools/assemble_delivery_tree.py`
   （`--package` 轻量包 + `--volumes` 分卷目录 + `--out` 交付目录）。
2. 组装后必须校验全部三样：根清单 82 条、`04_镜像/CHECKSUMS.sha256` 6 条、
   `cat part_* | sha256sum` = `c541042f…`。
3. **任何位于 E 盘的哈希结论都不可信**，需在 D 盘复算后才可采信。
4. 建议检查该盘的 USB 线缆/接口/供电，并跑 `chkdsk E: /f`；
   在确认稳定之前不要用它传递交付物。
