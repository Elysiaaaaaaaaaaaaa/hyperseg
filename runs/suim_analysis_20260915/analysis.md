# SUIM few-shot 实验诊断与下一轮建议

日期：2026-09-15。依据已下载的 16 份 summary.json、统一训练日志及当前本地实现。所有分数均为百分数；“提升”单位为百分点。

## 1. 结论

优先保留 adapter + 2000 steps 作为基线，检查支持集、修正分类头学习率配置，再做尺度和少量骨干参数微调的对照。现有证据支持“200 步预算不足”，尚不能证明“2000 步后继续训练必然提升”。PF 植物/海草和 RO 机器人/仪器是主要弱类。

这套 SUIM 实验调用 `tools/model_1.py` 的单图 v2 模型，是支持集监督微调；没有调用 `fewshot_hyperseg` 的 episodic 模型。`adapter` 更新 scene、modulation、fusion、low_rank、decoder、boundary_refine 和两个 head，不能将全部收益归因于 low-rank adapter。

## 2. 已完成结果

| 更新范围 / steps | 1-shot | 2-shot | 5-shot | 10-shot |
|---|---:|---:|---:|---:|
| adapter / 200 | 20.27 | 21.72 | 20.34 | 18.41 |
| adapter / 2000 | **27.13** | **33.40** | **40.26** | **43.56** |
| semantic-head / 200 | 2.09 | 2.20 | 2.29 | 2.39 |
| semantic-head / 2000 | 16.56 | 17.48 | 16.06 | 16.26 |

- 全部为训练 seed=3407，官方 TEST 110 张；日志以 ALL_DONE 结束。
- 实际支持图数分别为 8、16、40、79。完整语义 mask 中还包含其他类，因此 K 表示每类指定选取 K 张，未必意味着每类实际只被监督 K 次。
- 从 200 到 2000 步，adapter 分别提高 6.86、11.68、19.92、25.15 个百分点。200 步时“shot 越多反而越差”不宜解释为数据无益。
- 若 batch size 为当前默认值 2，200 步平均每张支持图被采样约 50、25、10、5.1 次；2000 步为其十倍。这是有放回采样的期望次数，不是严格 epoch 数。
- 已从 16 份混淆矩阵独立重算 mIoU，均与 summary 一致。类别 0 为有效 BW，当前 SUIM 损失与评估包含 0..7，未发现误套 UAV ignore_index=0 的问题。

## 3. 泛化与薄弱类别

adapter / 2000 最后 20 个打印点的训练 loss 均值：1-shot=0.0974，2-shot=0.1293，5-shot=0.1754，10-shot=0.2589。少样本训练损失低、测试表现低，说明拟合支持图不等于泛化；没有中间验证指标，不能据此确定过拟合发生在哪一步。

最佳现有设置（adapter / 2000 / 10-shot）的每类表现：

| 类别 | IoU | 召回率 | 精确率 | 主要错误 |
|---|---:|---:|---:|---|
| BW 背景/水体 | 82.22 | 87.64 | 93.00 | 部分识别为 SR |
| HD 潜水员 | 49.62 | 74.31 | 59.90 | 14.8% 的 HD 像素被判为 RO |
| PF 植物/海草 | **10.12** | **12.38** | 35.68 | 38.8% 被判为 WR，35.7% 被判为 RI |
| WR 沉船/遗迹 | 32.52 | 70.08 | 37.76 | 对其他类存在较多误报 |
| RO 机器人/仪器 | **19.29** | 40.82 | **26.77** | 32.4% 被判为 HD，21.0% 被判为 WR |
| RI 珊瑚礁/无脊椎 | 55.66 | 69.22 | 73.97 | 13.0% 被判为 WR |
| FV 鱼类 | 47.95 | 61.27 | 68.81 | 12.5% 被判为 WR |
| SR 沙地/海底/岩石 | 51.10 | 65.30 | 70.16 | 13.0% 被判为 WR |

PF 主要表现为漏检；RO 同时有漏检和较多误报，直接大幅提高 RO loss 权重可能进一步损害精确率。应分别检查 PF 支持样本覆盖与 RO/HD 的区分能力。

下载包没有 SUIM 每次运行的 `run_config.json`、`selection.json`、逐步 `history.jsonl`，也没有该服务器协议的完整清单与 `dataset_audit.json`。应补齐这些小文件，确认实际 lr、crop、batch、类别权重、checkpoint 来源及源代码版本。下文涉及 lr=1e-4、crop=512、batch=2 的诊断以当前代码默认值为依据，并非从缺失的运行配置中确认。

### 建立独立开发验证协议

当前只在最终步评估 TEST，没有训练中的验证集。后续调学习率、尺度和停止步数，应使用独立开发验证集；最终配置确定后再统一测试。

若从 SUIM 剩余 train_val 中划分开发集，应排除所有保留的 10-shot support，并检查近重复图像；明确披露使用了额外目标域标注来选超参数。若采用严格 K-shot 标注预算，应采用协议允许的源域/独立开发任务选超参数，或在支持集内部做可行的交叉验证；1-shot 无法自然提供每类独立留出图。不同验证预算不应混报。

## 5. 按收益与成本排序的优化

### A. 优先修正随机分类头与迁移模块共用小学习率的问题

当前 `load_v2()` 随机初始化 8 通道 head；优化器让 head 与所有非 encoder 模块共用 `--lr`，默认为 1e-4，并从第 1 步开始 polynomial 衰减。semantic-head / 2000 的训练 loss 仍高，说明尚不能把其较差结果全部归因于冻结特征不适合 SUIM，也可能没有把新 head 训练充分。

建议小范围对照，以下数值是待验证候选：

- semantic-head：保持 2000 步，lr 尝试 3e-4、1e-3，与现有 1e-4 比较。
- adapter：其余可训练模块保持 1e-4，head 单独设 1e-3。需要新增 head 参数组；直接把现有 `--lr` 改为 1e-3 会提高所有非 encoder 参数的学习率，不是同一个实验。
- 先固定训练步数与其他设置，观察分项 CE/Dice、梯度范数和验证指标；不要同时改 head 初始化、增强和损失。

### B. 检查训练与推理的目标尺度差异

当前训练公式为 `scale=max(uniform(0.75,1.5),512/min(image.size))`，随后裁剪 512×512；评估直接输入原图。本地检查了全部图像头信息：训练集 1525 张中 1237 张为 640×480，测试集 110 张中 92 张为 640×480；两者短边中位数均为 480。因此最常见图像训练时放大约 1.07–1.5 倍，测试时保持原尺寸。尺度差异存在，但不宜夸大为数倍放大；其影响尚未验证。

公式在短边小于约 341 时会使随机 scale 完全失效，但本地 SUIM 没有此类图像，所以这不是本次结果的实际解释。

先在开发集比较同一 checkpoint 的原尺寸推理和等比例短边 512 推理；后者应将 logits 双线性缩回原图后 argmax，并在原始 mask 上计算指标。这样可保留原尺寸评估口径。若有稳定收益，再试短边 384/512 的匹配训练；水平翻转 TTA 放到后续单独测试。

### C. 针对弱类改进裁剪质量

已有实现会从该图指定的目标类别中选一个，再保证裁剪包含该类一个像素；不能再把“添加目标类别裁剪”当作尚未实现的功能。

应统计增强后每类像素占比和有效 batch 次数，重点看 PF/RO。可增加有限次重采样，使目标类在 crop 内达到适当像素数/占比；对小目标保留退路，不应强迫所有图达到相同的大面积阈值。同时保留适量完整场景或普通裁剪，避免训练集充满前景特写。

当前已经使用支持集逆对数频率加权 CE 和 Dice。先检查实际权重与增强后分布，再考虑权重限幅或重新平衡；不建议优先叠加更多 loss。

### D. 在 5/10-shot 上试少量骨干参数适配

航拍到水下存在输入与语义差异，adapter 模式完全冻结 encoder。这是限制性能的合理假设，但尚未通过骨干消融验证。

在 A/B 验证后，尝试只解冻 SegFormer 最后一阶段：encoder lr=1e-5、其余模块=1e-4、head=1e-3；其余保持一致。当前只有 full 模式会解冻整个模型，最后阶段微调需要新增模式。先在 5/10-shot 验证，1-shot 不优先扩大训练参数量。

部分骨干微调有 few-shot segmentation 研究依据，例如 [SVF（NeurIPS 2022）](https://arxiv.org/abs/2206.06122) 通过只更新奇异值进行适配；这支持探索受限骨干更新，但不能作为本项目“解冻最后阶段必然提高”的证据。

### E. 最后再加训练预算、BN 或初始化消融

- 若开发集曲线在 2000 步仍上升，再比较 4000 步；1-shot 已能拟合支持集，不宜直接全矩阵加长。
- 200 和 2000 步使用不同总周期的学习率衰减，因此 200 步结果不是 2000 步长训练中第 200 步的结果，不能当作同一条测试学习曲线。
- 当前 BN running statistics 全冻结，可能保留源域统计。可单独测试仅用 support 做 BN 校准，但 batch=2 下直接全面解冻统计不一定更好；不能使用 TEST 更新 BN。
- `semantic-map` 为已有选项，但 Water→BW、Vegetation→PF 等映射只近似成立。作为独立初始化消融，不应混入随机 head 的公平比较。

## 6. 建议下一轮最小实验矩阵

先补齐配置、锁定原 support 和开发评估协议。以 5-shot、seed=3407、2000 steps 做小规模定位，现有结果仅作 TEST 基线参考。

| 实验 | 改动 | 目的 |
|---|---|---|
| A0 | 复现原 adapter，并记录开发验证曲线 | 建立可比的开发基线 |
| A1 | A0 + head lr=1e-3，其余=1e-4 | 验证随机 head 学习是否不足 |
| H1/H2 | semantic-head，lr=3e-4 / 1e-3 | 检查现有 head-only 对照是否训练充分 |
| S1 | A0/A1 同一 checkpoint，原尺寸与短边 512 推理 | 无需重新训练地检查尺度影响 |
| A2 | 最佳配置 + 有效目标面积裁剪 | 检查 PF/RO 的有效监督 |
| A3 | 最佳配置 + 最后一阶段 encoder lr=1e-5 | 检查水下特征适配 |

逐项引入变化，不必一次跑全。确定配置后，再覆盖 1/2/5/10-shot 与 3407/3408/3409 三个训练 seed。固定支持集时，这三个 seed 只衡量初始化与训练随机性；若要衡量支持集敏感性，另做多个 selection seed，并分开报告。

建议新增日志：分项 CE/Dice/boundary、各参数组 lr、梯度范数、增强后每类像素统计、开发集 mIoU/逐类 IoU、固定支持图的无增强指标和可视化。测试集仅保留最终报告用途。
